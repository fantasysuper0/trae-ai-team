# 代码审查技能

## 描述
对当前分支相对主分支的代码变更进行全面审查，输出结构化的审查报告。

## 何时使用
- 合并前代码审查
- 自测失败后排查
- 重构后稳定性检查
- SOLO Coder 在代码合并前的最终审查

## 指令

### 第一步：获取变更范围
识别当前分支相对 main 分支的所有变更文件。

### 第二步：逐文件审查
对每个变更文件，从以下维度审查：

| 维度 | 检查项 |
|------|--------|
| **正确性** | 逻辑错误、边界条件、空值处理、类型安全 |
| **安全性** | 注入风险、XSS、认证绕过、敏感信息泄露 |
| **性能** | N+1 查询、内存泄漏、不必要的计算、大循环 |
| **可维护性** | 命名清晰度、函数长度、重复代码、耦合度 |
| **测试** | 测试覆盖率、测试质量、边界条件测试 |
| **规范** | 编码规范一致性、Git 提交信息规范 |

### 第三步：输出审查报告
按文件分组，每个问题标注严重程度：

```
## 文件：src/services/user.ts

### 🔴 严重 — SQL 注入风险（第 42 行）
```typescript
// 问题代码
const query = `SELECT * FROM users WHERE id = ${userId}`;
// 建议修复
const query = `SELECT * FROM users WHERE id = $1`;
```

### 🟡 建议 — 缺少空值检查（第 58 行）
```typescript
// 问题代码
return user.name.toUpperCase();
// 建议修复
return user?.name?.toUpperCase() ?? '';
```
```

## 注意事项
- 只提有价值的建议，避免噪音
- 每个问题必须给出具体的修复方案和代码示例
- 优先报告严重程度高的问题
- 如果代码质量良好，明确说明
