# API 契约验证流程

> 手动触发：在对话中使用 `#api-contract-rule` 引用。

## 验证步骤

### 1. 加载契约文件
读取 `docs/api-contract.yaml`，解析所有 API 端点定义。

### 2. 扫描实际实现
扫描 `src/routes/` 目录下所有路由文件，提取实际注册的端点。

### 3. 逐项对比
对每个端点检查以下一致性：

| 检查项 | 说明 |
|--------|------|
| 路径匹配 | 契约路径与路由路径是否一致 |
| HTTP 方法 | 契约方法与路由方法是否一致 |
| 请求参数 | 契约定义的参数与实际接收的参数是否一致 |
| 响应格式 | 契约定义的响应 Schema 与实际返回是否一致 |
| 状态码 | 契约定义的状态码与实际返回是否一致 |

### 4. 输出报告
按严重程度分类输出：

- 🔴 **阻断性不一致**：路径/方法不匹配，会导致前后端对接失败
- 🟡 **非阻断不一致**：参数/响应细节差异，可能导致运行时错误
- 🟢 **建议项**：命名规范、文档完整性等改进建议

### 5. 修复建议
对每个不一致项给出具体的修复方案，指明需要修改的文件和位置。
